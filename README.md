# Brainwork

Sistema pessoal de conhecimento e operação de QA: diário de testes, ciclo de demandas, sanidades/regressão, base de conhecimento, estudos e arquivamento — com skills, templates e automações de apoio.

> https://github.com/RafaCartaxo/brainwork

## O que é

- Diário de testes e ciclo de demandas (DEV → HML → concluídas).
- Sanidades, checklists e regressão padronizados.
- Base de conhecimento, refinamento e estudos ad hoc.
- Skills, templates e scripts de apoio à operação.

## O que não é

- Não é um produto comercial nem uma regra de negócio.
- Não é um relato de cliente: contextos de trabalho aparecem apenas como casos abstratos e sanitizados.
- O vault bruto com notas do dia a dia não é a narrativa principal.

## Como navegar (sem Obsidian)

- [`QA Workspace/`](QA%20Workspace/) — operação de QA (Inbox, Daily, Demandas, Sanidades, Conhecimento, Refinar, Estudos, Arquivo).
- [`Sistema/`](Sistema/) — configuração: contexto, skills, specs, templates, scripts.
- [`Ambiente/`](Ambiente/) — contexto de ambiente de trabalho.

> Links internos usam sintaxe Obsidian `[[...]]`; no GitHub web eles não navegam como páginas. Use a árvore de arquivos.

## Escopo e limites

- Repositório público, mas partes do histórico citam fluxos/módulos de trabalho. Esses trechos devem ser lidos como casos abstratos; detalhes de clientes, demandas ou conteúdo proprietário não fazem parte da apresentação.
- Sem métricas sem fonte verificável.
- Este README é camada de apresentação; não altera o vault existente.

## Uso no portfólio

Apresentar como método de operação de QA com rastreabilidade, com 1–2 casos sanitizados (demanda → critérios → casos → validação).
